## 1. 这是什么

**帽兜工具**（英文名 **LIWEN Tool**）是一款面向 Windows 的桌面工具箱（基于 PyQt6，同时可在 macOS / Linux 上运行，
仅资源管理器右键菜单与图形安装程序为 Windows 专属），把 8 大类实用能力收进同一个深色界面：

| 分类 | 功能 |
|---|---|
| 🖥 本机 | 压缩解压、磁盘空间索引 |
| 🌐 局域网 | 文件传输、联机大厅（房间 / 语音 / 房间内文件传输） |
| ☁️ 互联网 | 可视化网页爬虫、HTTP 请求发送、生成式 AI 对话、反向代理 |
| ⚙️ 设置 | 个性化设置、故障检测与一键修复 |
| ℹ️ 关于 | 版本与作者信息 |

界面标题栏为自绘（无系统边框），顶部显示 logo 与「帽兜工具」，右下角可拖拽缩放。
主题为 Catppuccin Mocha 风格的深色配色，**强调色可切换**（默认蓝 / 紫 / 绿 / 橙 / 红）。

## 3. 功能详解

### 3.1 压缩解压

**能力**：把文件/文件夹打包为多种归档格式，或解压、预览归档内容。

**支持的格式**

| 格式 | 扩展名 | 压缩 | 解压 | 密码 | 分卷 |
|---|---|:--:|:--:|:--:|:--:|
| ZIP | `.zip` | ✅ | ✅ | ✅（AES） | — |
| 7z | `.7z` | ✅ | ✅ | ✅ | ✅ |
| TAR | `.tar` | ✅ | ✅ | — | — |
| TAR.GZ | `.tar.gz` `.tgz` | ✅ | ✅ | — | — |
| TAR.BZ2 | `.tar.bz2` `.tbz2` | ✅ | ✅ | — | — |
| TAR.XZ | `.tar.xz` `.txz` | — | ✅ | — | — |
| SHISHAN | `.shishan` | — | ✅ | ✅ | — |
| ZHANS（阵格式） | `.zhans` | ✅ | ✅ | ✅ | — |

**专有压缩刻度（0–10 级）**

这是本工具的特色机制。刻度 **0 = 标准输出**，**1–10 = 启用自研压缩策略**：

- 0 级：产出标准格式文件，可被 WinRAR / 7-Zip / `unzip` 等通用工具直接打开
- 1–10 级：启用**去重**（按内容哈希跳过重复数据块）、**逐文件 zlib 策略选择**、
  可选的**自定义种子码**，并把结果封装进 `.zhans` 容器

> ⚠️ **重要**：等级 > 0 时，即使选择了 ZIP/7z/TAR，产物实际是 `.zhans` 容器
> （文件头为 `ZHA\x01`），**通用工具无法打开**，需用本工具解压。
> 需要标准压缩包时请把等级设为 0。

**其它特性**

- **逐文件独立设置**：列表中每个文件可单独指定格式、输出路径、密码、分卷大小
- **归档预览**：表格展示归档内容（名称/大小/压缩后大小），支持选择性提取单个文件
- **分卷压缩**：仅 7z 支持
- **自定义种子码**：仅 `.zhans` 格式，用于产出可复现的定制压缩结果

### 3.2 空间索引

**能力**：扫描磁盘，可视化分析空间占用。

- 选择盘符/根路径后扫描，扫描在后台线程进行，带进度条
- **条形图**：以横向条形图展示占用最大的前 80 项
- **树形视图**：可排序列（名称 / **占用** / 占比 / 项目数），逐级展开、按需加载
- 结果持久化到 SQLite（`data/space_index_<盘符>.db`），**可反复查询无需重扫**
- 扫描为两阶段：层序并行遍历（边扫边批量入库）→ 反向汇总目录大小
- **「占用」= 磁盘实际分配的空间**，与访达「占用空间」、`du`、资源管理器
  「磁盘上的大小」同口径；稀疏文件按真实占用计（不再是表观大小）
- **跨平台挂载点**：Windows 列出所有盘符，macOS 列出 `/` 与 `/Volumes/*`，
  Linux 用 `psutil` 列出真实挂载点（外接盘不再看不到）
- macOS 的固件链接目录（如 `/System/Volumes/Data/Users` 与 `/Users` 实为同一目录）
  会**自动去重**，不会把同一份数据算两遍

> 缓存文件可安全删除，删除后需重新扫描。占用空间可能较大（实测可达数 GB）。

---

### 3.3 局域网传输

**能力**：在同网段设备间直接收发文件，无需服务器。

- **发送模式**：自动发现局域网在线设备，或手动输入 IP；支持 ping 连通性检查
- **接收模式**：开启监听后广播自身，等待其他设备发送
- **自动压缩**：发送前自动打包为临时 ZIP 以提高小文件传输效率，接收端自动解压并清理临时文件
- **请求确认**：接收方会收到确认弹窗，可接受或拒绝；设置中可开启「自动接收」跳过确认
- 传输时可设置发送者昵称，接收端可看到来源

**技术要点**：TCP 传输（默认 12345），UDP 广播发现（12346）。

### 3.4 联机大厅（房间 / 语音 / 文件传输）

用于让多台设备像在同一个局域网内一样联机游戏。**联机走纯应用层组网：不需要虚拟网卡、
不需要 TUN 驱动、不需要管理员权限**，Windows / macOS / Linux 上是同一套代码，可以跨平台混合联机。

界面只有两种形态：

| 形态 | 说明 |
|---|---|
| **LobbyView（大厅）** | 创建房间（房间名、密码、通信端口、最大玩家数）、扫描局域网已有房间、已保存房间列表，以及**直连加入**（填房主 IP + 房间端口） |
| **RoomPage（房间）** | 唯一的房间内视图：基于**真实局域网 IP** 通信，支持**实时成员名单、语音、房间内文件互传** |

**联机是怎么组网的**

1. **广播发现**：房主在局域网内周期性 UDP 广播房间公告（12347），同网段的设备
   扫描即可看到房间，点一下就能加入。
2. **直连加入**：广播被 AP 隔离 / 跨网段时，在大厅右侧「直连加入」填入房主的
   **真实 IP + 房间端口**（如 `192.168.1.20:12345`）。程序会先向该地址发一次
   直连探测（`room_probe`）取回「房间名片」——字段与广播公告完全一致、**不含会话凭证**——
   再走同一套挑战-应答流程加入。
3. 房间通信使用**真实局域网 IP**，不分配虚拟 IP、不修改系统路由表，因此不会与
   VPN、虚拟机网卡、杀软冲突。

**成员名单**

- 进入房间后每 3 秒与房主心跳一次，房主的应答里**携带完整成员名单**
- 「在线成员」显示昵称、IP，并标注「房主 / 本机」
- 房主重启或本机被剔除时，会明确提示「会话已失效，请重新加入房间」，
  而不是停在一个永远不更新的房间里

**语音通话**

- 局域网 UDP 单播实现全双工语音，无需服务器
- 参数：16 bit 单声道、22050 Hz、20ms/帧、200ms 抖动缓冲
- 发送目标随成员名单自动更新
- **音频后端跨平台**：优先 `sounddevice`（已列入 `requirements.txt`，各平台与各
  Python 版本都有 wheel），缺失时自动回退 `pyaudio`；两者都没有时语音按钮禁用并
  提示安装，房间其余功能不受影响（可在故障检测页一键安装）

**房间内文件传输**

- 进入房间即开始监听该房间的传输端口，其他成员可直接发文件给你
- 「发送给」可选**全部成员**或指定某个成员，支持多文件
- 复用「局域网传输」同一套协议：自动压缩、请求确认、断点保护、原子落盘
- 接收位置与「局域网传输」共用「默认接收目录」设置；勾选「自动接收」可免确认

**房间协议**

- UDP 12347 广播房间公告；**TCP「房间端口 + 1」（默认 12346）**处理加入请求与直连探测
- 加入采用**挑战-应答认证**（`SHA256(密码哈希 + 随机数)`），密码不裸传
- 心跳间隔 3 秒，超时 10 秒判定对端离线；心跳应答同时下发成员名单
- 房间内文件传输使用由房间端口推导的专用端口（12800–13199，默认 12345 → 13160）

### 3.5 可视化网页爬虫

**能力**：不写代码，通过点击网页元素生成抓取规则。

**配置流程**

1. 内嵌 Chromium 浏览器打开目标网址
2. **元素拾取模式**：鼠标悬停高亮，点击捕获该元素的 **CSS 选择器 + XPath + 文本**
   （选中元素显示绿色高亮，所有匹配元素显示黄色，按 `Esc` 退出拾取）
3. 配置字段抽取规则（字段名 + 选择器 + 类型），右侧实时预览抽取结果
4. 配置翻页：下一页选择器 或 URL 规律（如 `?page={n}`）
5. 设置反爬选项：请求间隔、超时、重试次数、User-Agent、代理
6. 选择**调试模式**（少量页面验证）或**完整爬取**
7. 结果以表格预览，可导出（含 Excel）

**站点可行性检测**

爬取前可先检测目标站点：robots.txt 规则、是否需要 JavaScript 渲染、
是否有 CAPTCHA、Cloudflare 等反爬/CDN 特征，并给出可行性报告。

> 内嵌浏览器**仅用于可视化配置**。实际爬取由 `requests` + `lxml` 执行，速度更快。

### 3.6 请求发送（HTTP 调试）

类 Postman 的 HTTP 调试工具。

- **方法**：GET / POST / PUT / DELETE / PATCH / HEAD / OPTIONS / TRACE
- **URL**：自动补全 `http://`
- **Params 标签**：查询参数键值表
- **Headers 标签**：键值表，支持批量粘贴解析
- **Body 标签**，5 种模式：
  - `none` — 无请求体
  - `form-data` — 表单（含文件上传）
  - `x-www-form-urlencoded` — 表单编码
  - `raw` — 原始文本（JSON 编辑器，带格式化/校验按钮）
  - `binary` — 二进制文件
- **响应区**：状态码、耗时、大小；响应头 / Cookie 分区展示
- **历史记录**：自动保存请求历史，可收藏为集合
- **变量**：支持 `{{变量名}}` 占位替换，变量可持久化

### 3.9 故障检测与修复

**两种检测模式**

| 模式 | 覆盖范围 |
|---|---|
| **局域网检测** | 网卡接口、子网冲突、端口 12345/12346/12347 占用、UDP 广播能力、设备发现、房间扫描、音频后端与语音协议可用性 |
| **基础检测** | 压缩模块可用性、配置文件完整性、空间索引（sqlite3、可写性、扫描引擎、缓存完整性）、AI 功能（requests、API 配置、端点可达性、会话存储）、请求发送（requests/urllib、worker、页面、历史、变量、基础连通性） |

「全局检查」会串行执行两套检测。

**两种修复方式**

1. **一键修复** —— 在当前进程内执行修复，完成后自动重跑检测验证结果
2. **进行修复** —— 把问题序列化为 `repair_task.json`，启动独立的
   `LIWENTool_Repair` 修复程序，主程序退出；修复完成后修复程序重新拉起主程序

**可修复项**：释放被占端口、安装音频后端（`sounddevice`）、修复配置文件、重置空间索引数据库、
重置 AI 配置、修复对话存储、修复请求历史、重置 HTTP 变量。

通过文件锁避免多个修复实例同时运行。

### 3.11 反向代理（v6.0.0 正式上线）

把**本机一个固定入口**转发到**预先配置的上游**，用于客户端里域名/端口写死、
不方便改代码的联调场景（手机 App、只能装真机的 SDK、第三方回调接收）。

**典型用法**

```bash
# App 里写的是 https://api.example.com，把它指到本机入口
# 规则：监听 127.0.0.1:8888 → 上游 https://api.example.com
# 然后把 App 的 hosts（或 BASE_URL）改成本机地址即可，不用改请求代码
```

**规则字段**（界面「新建规则」或在 `proxy_rules.json` 里直接写）

| 字段 | 说明 |
|---|---|
| 名称 | 仅用于显示 |
| 监听地址 / 端口 | 默认 `127.0.0.1:8888`；填 `0.0.0.0` 可让局域网设备接入（有风险提示） |
| Host 匹配 | 留空 = 该端口的兜底规则；填 `api.example.com` 或 `*.example.com` 则按请求 Host 分发。**同一个端口可以挂多条规则**（多个域名共用一个入口） |
| 上游目标 | `http://` 或 `https://` 基址，可带路径前缀（如 `https://x.com/base`） |
| 剥离路径前缀 | 入口路径命中则去掉（`/api/echo` + strip `/api` → 上游收到 `/echo`） |
| 追加路径前缀 | 转发前往路径前追加 |
| Host 头覆盖 | 留空则自动用上游 host |
| 回写 Location | 上游 `302` 指回自己的域名时，改写成入口地址（默认开） |
| 校验上游证书 | 上游是自签证书时关闭（默认开） |
| 入口证书 / 私钥 | 需要「客户端 → 代理」也走 HTTPS 时填，界面可一键生成自签证书 |
| 请求头/响应头改写 | 键值表；**值留空 = 删除该头** |
| 允许 CONNECT | 允许客户端用 `CONNECT` 打隧道，但**只放行到本规则上游** |

**多个域名共用一个入口**

`Host` 匹配让「一个端口」服务多个上游，这对只能改 hosts、不能改端口的客户端尤其有用：

| 规则 | 监听 | Host 匹配 | 上游 |
|---|---|---|---|
| 兜底 | `127.0.0.1:8888` | （留空） | `http://127.0.0.1:9000` |
| 线上 API | `127.0.0.1:8888` | `api.example.com` | `https://api.example.com` |
| 测试环境 | `127.0.0.1:8888` | `*.test.example.com` | `https://test.internal` |

请求带 `Host: api.example.com` 就走线上 API，带 `Host: v1.test.example.com` 就走测试环境，
其余 Host 走兜底。匹配顺序是**精确 → 通配（取最长）→ 兜底**，忽略大小写与端口；
若一个端口上全是 Host 规则且都不匹配，返回 `404` 并说明原因。
同一端口上**只能有一条兜底规则**，且多条规则必须用同一份入口证书（冲突时启动会如实报错）。

**界面**

- 规则表：启用 / 名称 / 监听 / Host 匹配 / 上游 / TLS / 状态，双击编辑，右键菜单（编辑/复制/删除/单独启动）
- 启动 / 停止 / 重启：在后台线程执行，不卡界面；部分规则起不来会**逐条**显示原因
- 访问日志：时间、规则、方法、路径、状态、耗时、出入字节、错误（最多保留 2000 行）
- 统计：总请求 / 错误 / 流入 / 流出 / 活动连接，以及按规则细分

**自动补齐的转发头**

`Host`（改写为上游）、`X-Forwarded-For`（保留客户端原值并追加）、
`X-Forwarded-Proto`、`X-Forwarded-Host`、`Via: 1.1 LIWENTool`；
hop-by-hop 头（`Connection`/`Keep-Alive`/`TE`/`Transfer-Encoding`/`Upgrade`/
`Proxy-*`）一律不转发，`Connection` 里点名的自定义头同样剥离。

**如实说明的限制**

- **不做 MITM 解密**：不会解密客户端发往真实域名的 HTTPS（那需要在客户端装根证书，
  属于中间人行为）。只做「入口 TLS 终止（自签需客户端信任）」与「上游 TLS」。
- **只支持 HTTP/1.1**：上游与客户端都按 1.1 处理，HTTP/2 请求会被拒绝（400）。
- **不是开放代理**：`CONNECT` 只能连到规则配置的上游，其它目标一律 403。
- **日志只记元数据**：不落盘请求/响应内容，避免把用户凭据写进日志。

## 5. 端口与协议速查

| 用途 | 端口 | 协议 |
|---|---|---|
| 文件传输 | 12345 | TCP |
| 设备发现广播 | 12346 | UDP |
| 房间公告 / 发现 | 12347 | UDP |
| 加入房间 / 直连探测 | 房间端口 + 1（默认 12346） | TCP |
| 房间语音 | 12400–12799（由房间端口推导） | UDP 单播 |
| 房间内文件传输 | 12800–13199（由房间端口推导，默认 12345 → 13160） | TCP |
| 本地 Mock API 服务器 | 8700 | HTTP |
| 反向代理入口 | 自定义（默认 `127.0.0.1:8888`） | HTTP / HTTPS（可终止 TLS） |

**语音参数**：22050 Hz、单声道、16 bit、20 ms/帧、200 ms 抖动缓冲。

> **关于语音端口**：早期版本固定使用「房间端口 + 2」，默认配置下等于 12347，
> 与房间发现端口冲突，导致房主一侧语音无法启动。现由
> `voice_port_for_room(room_port)` 从 12400–12799 区间推导，同一房间内所有
> 参与者算出的端口一致，无需额外协商，并已避开 12345 / 12346 / 12347。
>
> **关于反向代理端口**：入口端口完全由用户指定，**但 12345/12346/12347 会被拒绝**
> （本应用自身端口），同一端口只能被一条规则占用；端口被其它程序占用时界面会
> 显示「端口 N 已被占用」而不是假装启动成功。
>
> **关于加入端口与房间文件端口**：加入服务固定监听「房间端口 + 1」（默认 12346，TCP）；
> 房间内文件传输由 `room_data_port_for_room(room_port)` 从 12800–13199 推导
> （默认 12345 → 13160），推导时会跳过 12345/12346/12347、房间端口、房间端口+1
> 与同一房间的语音端口。

## 8. 已知限制

1. **等级 > 0 的压缩产物非标准格式**：会被封装为 `.zhans` 容器，
   通用解压工具无法打开，需用本工具解压。需要标准格式请用等级 0。
2. **TAR.XZ 与 SHISHAN 仅支持解压**，不支持压缩。
3. **密码支持不统一**：TAR 系列（tar / tar.gz / tar.bz2 / tar.xz）不支持密码；
   仅 ZIP、7z、SHISHAN、ZHANS 支持。
4. **分卷压缩仅 7z 支持**，产物命名为 `<文件名>.7z.001`、`.002` …；
   解压时选择第一个分卷（或主文件名）即可。
5. **联机语音需要音频后端**：优先 `sounddevice`（已随 `requirements.txt` 提供），
   缺失时自动回退 `pyaudio`；两者都没有则语音按钮禁用并提示安装，
   房间其余功能（成员名单、房间内文件传输）不受影响。
6. **空间索引缓存可能非常大**（取决于磁盘容量），建议定期清理或在故障检测页重置。
7. **爬虫尊重目标站点规则**，请自行确认合规使用。
8. **反向代理不做 HTTPS 中间人解密**：要观察客户端发往真实域名的 HTTPS 明文，
   必须在客户端设备安装根证书（MITM），本工具不提供；它只做「入口 TLS 终止」
   （自签证书需客户端信任）与「上游 TLS 传输」。
9. **反向代理只支持 HTTP/1.1**：上游与客户端都按 1.1 处理，HTTP/2 请求会被拒绝（400）。
   `CONNECT` 只放行到规则配置的上游，不是开放代理。
10. **反向代理的访问日志只在内存中保留最近 500 条事件**（界面显示 2000 行），
    不落盘、不记录请求/响应正文，避免把凭据写进磁盘。

2. **局域网里有人发畸形数据包，也不会再让联机功能"哑掉"**。此前一个 5 字节的
   伪造广播包就能让「扫描房间」「设备发现」或房主的房间广播永久失效（房间还在，
   别人却再也扫不到，界面无任何提示）。现在协议边界只接受合法对象，畸形包直接被丢弃，
   功能继续工作。
3. **探测/加入失败时给出的是真正的原因**。对端不是本程序、或包头被破坏时，
   命令行与联机大厅会显示「协议错误: 包头不是 JSON 对象」这类明确信息，
   而不是抛出内部异常。
4. **测试更真**：新增对抗性测试脚本 `code/tools/fuzz_multiplayer.py`（15 项：端口推导
   穷举 6.5 万组、103 组畸形应答、畸形 UDP、人数上限、资源泄漏等），并把关键回归固化进
   `verify_multiplayer.py`。两个脚本不能同时运行（都要占 UDP 12347）。

## 9.5 版本 6.0.0 的反向代理（用户可感知）

> **版本说明**：反向代理在开发周期里的内部编号是 `4.19.0`（**从未打 tag、从未发版**），
> 本次随 **6.0.0 正式上线**，成为「互联网」分类下的第 4 个子标签。属于「重要新功能」，
> 按版本规则递增主版本位（用户明确指定 6.0.0）。详见 `开发文档.md` §12.3。

**新增功能：互联网 → 反向代理**（第 4 个子标签），另附 4 条 CLI 命令
（`proxy-list` / `proxy-add` / `proxy-rm` / `proxy-serve`）。

1. **客户端里写死的域名/端口，不用改代码就能联调**。新建一条规则
   （本机入口 → 固定上游），把 App 的 hosts 或 BASE_URL 指到本机入口即可；
   路径前缀可剥可加，`Host` 自动改写，`Location` 自动回写成入口地址。
2. **WebSocket 与 `CONNECT` 隧道可用**，但 `CONNECT` 只放行到该规则配置的上游，
   打别处一律 403 —— 它是有规则的代理，不会被当成开放代理滥用。
3. **入口与上游两侧的 TLS 都支持**：上游自签证书可关闭校验；需要「客户端 → 代理」
   也走 HTTPS 时，对话框里可一键生成自签证书（**需要客户端信任该证书**）。
4. **规则热生效**：不停止服务就能增删规则；启动状态如实显示「运行中 N 条规则」或
   「部分失败：N 条未启动 + 原因」，端口被占用会明说「端口 N 已被占用」。
5. **访问日志与统计**：时间 / 规则 / 方法 / 路径 / 状态 / 耗时 / 出入字节 / 错误，
   界面保留最近 2000 行；**只记元数据，不记录请求与响应正文**，避免把凭据落盘。
6. **实现期修掉的 3 个真实缺陷**（都由测试抓出）：分块（chunked）响应曾被剥掉
   `Transfer-Encoding` 导致客户端挂到超时；请求头里的裸 `CR`/裸 `LF` 与重复且冲突的
   `Content-Length` 曾被放行（头注入 / 请求走私温床），现在两者都直接 400；
   规则热删除曾留下永不退出的线程（macOS 上关 socket 唤不醒阻塞读），现在改为可轮询状态位。
7. **测试**：新增 `code/tools/verify_reverse_proxy.py`（119 项）与
   `code/tools/fuzz_reverse_proxy.py`（41 项，含 200 轮随机变异），全部通过；
   两个脚本只用本机临时端口，可与联机测试同时运行。

> **它不是 Reqable / Charles 那样的抓包工具**：不做 HTTPS 中间人解密（那需要往客户端
> 装根证书），也不支持 HTTP/2 与请求正文捕获。要做到「看明文」，只能走 MITM 方案。
